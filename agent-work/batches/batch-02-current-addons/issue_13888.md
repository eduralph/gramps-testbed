**Note 5** (azrdev - 2025-08-11 15:15)

Indeed generating thumbnails / sections of the original image for PDF use was intentionally proposed and implemented by me. The rationale is explained in the linked PR:

Having lots of big photos with small faces in my setup, this leads to unreasonably huge PDF files with unrecognizably small faces in them.
Also, some characters (e.g. comma, spaces) in filepaths might trouble the latex parser, see 75921ce and 2da93aa -- using thumbnails this is circumvented.
However, note this makes the resulting .tex file not standalone anymore.

As noted by codefarmer in email (thanks for the heads up!), we should try to reconcile both our requirements. Their Proposals:

Use a different algorithm for generating thumbnails which would result in better quality

the used method gen.utils.thumbnails.get_thumbnail_path() apparently defers to using a "thumbnailer" type plugin. Two of these are builtin:

GnomeThumb defers to detected binaries, apparently conforming to this invocation schema: https://askubuntu.com/questions/1368910/how-to-create-custom-thumbnailers-for-nautilus-nemo-and-caja and setting a maximum bounding box of 96x96 or 180x180 pixels ( https://github.com/gramps-project/gramps/blob/9aa8722/gramps/plugins/thumbnailer/gnomethumb.py#L94-L96 https://github.com/gramps-project/gramps/blob/9aa8722/gramps/gen/const.py#L291-L292 )
ImageThumb also uses these constants to calculate the bounding box to scale into: https://github.com/gramps-project/gramps/blob/9aa8722/gramps/plugins/thumbnailer/imagethumb.py#L85-L89

I think patching both to allow for more flexible size selection (and then requesting something like 256 or 512px for the PDF reports) would be feasible.
Otherwise, one could say we're want image cropping not thumbnailing, but then would have to implement this as a separate function (I have not checked if there's a facility for that somewhere). Probably want to abstract it away, so as not to have access to the relevant gtk functions in the treedoc.py

Apply the original filenames to the thumbnails so they remain identifiable.

Adding these as comments in the latex file seems like a good idea, retaining them (including all possible whitespace and special characters) in the filename would again start breaking latex syntax.
