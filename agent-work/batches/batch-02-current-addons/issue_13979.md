## ===== TRIAGE VERDICT =====

- **Actionable?** yes.
- **Where does the fix go? — VERIFY REPO FIRST.** The traceback path is
  `PluginManager/PluginManager.py` — the **"Plugin Manager Enhanced" addon**, NOT gramps
  core's Addon Manager (there are two; don't confuse them). **Confirm this addon lives in
  addons-source vs an external repo before coding** — like FTV, an "Enhanced"/community
  addon may be maintained elsewhere. If external, record the finding and stop; do not patch.
  If in addons-source, branch `maintenance/gramps61`.
- **Root cause (HYPOTHESIS — verify by reproducing):** `txt = " ".join(req_lst[0])` assumes
  `req_lst` is non-empty, but the PostgreSQL Enhanced row produces an empty `req_lst` (no
  requirements parsed in the expected shape), so `req_lst[0]` is out of range. The `__info`
  display code doesn't handle a plugin whose requirements list is empty/differently shaped.
- **Does the reporter's workaround match the root cause?** No real workaround; lordemannd's
  note about the install-doesn't-stick is a SEPARATE second bug (see below).
- **Fix sketch (pending repro):** guard the empty case in `__info` — `if req_lst:` before
  indexing, or build `txt` defensively from whatever `req_lst` actually contains. Read
  `__info` to see what `req_lst` is derived from and why the PostgreSQL Enhanced row yields
  empty; the right fix may be upstream of the join (the requirements parse) rather than at
  the join itself. Confirm which by inspecting `req_lst`'s contents at repro time.
- **SECOND BUG flag (note 2):** "installs but doesn't actually install" via the core Addon
  Manager is a DIFFERENT defect, possibly in core, possibly the same addon. Per CLAUDE.md
  "one issue per ticket," do NOT bundle — fix the IndexError here; file/raise the install
  issue separately if it reproduces.
- **Repro on example.gramps?** Tree-independent — it's a plugin-list interaction. Needs the
  Plugin Manager Enhanced addon installed + the PostgreSQL Enhanced row present in the list.
  No family data required.
- **Test location & type:** unit-testable IF `__info`/the requirements-parse can be exercised
  with a synthetic plugin entry whose requirements list is empty —
  `addons-source/PluginManager/tests/test_*.py` (create `tests/__init__.py` if absent).
  Construct the entry that yields empty `req_lst`, call `__info`, assert no IndexError. If
  too GUI-coupled, a `tests/interface/` test selecting the row. Try unit first.
