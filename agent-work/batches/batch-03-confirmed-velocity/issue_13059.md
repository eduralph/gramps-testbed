## Thread — EXACT repro provided
daleathan (note 1): duplicate of 0012659 (2022), nobody could reproduce then.
mihle (note 2): reproduces on 5.2.2, exact steps —
  1. Have an existing box on a photo, linked to a person.
  2. Drag a box EDGE to resize it.
  3. Release, then CLICK (not drag) inside the middle of that same box.
  → `TypeError: set_coords() argument after * must be an iterable, not NoneType`
     at gramps/gui/widgets/selectionwidget.py:742 (`self.current.set_coords(*self.selection)`).
  Does NOT fire if the post-resize action is a drag, a click outside, or a new box.

## ===== TRIAGE VERDICT =====
- **Actionable?** yes — precise repro in hand. Good "real bug" candidate.
- **Where? — CORE, resolve by reproducing.** The traceback is entirely in
  `gramps/gui/widgets/selectionwidget.py` — gramps CORE, not the Photo Tagging addon. The
  addon hosts the SelectionWidget; the defect is in core. Same core-vs-addon pattern as
  13326. Confirm by reproducing: if the crash is in selectionwidget.py regardless, PR
  targets ../gramps, not addons-source.
- **FIRST STEP — repro on gramps60** with mihle's exact steps (needs Photo Tagging addon
  + a photo with a person-linked box on example.gramps). Reported on 5.1.6/5.2.2 — confirm
  it still fires on 61 before fixing.
- **Root cause (hypothesis — verify):** at selectionwidget.py:742, `self.current.set_coords(
  *self.selection)` is called on the click-after-resize path, but `self.selection` is
  `None` in that specific sequence (resize leaves `current` set but `selection` cleared, and
  the plain-click handler doesn't rebuild it). `set_coords(*None)` → the TypeError.
- **Fix sketch:** guard the call — if `self.selection is None`, return / skip the
  `set_coords` rather than splatting None. Determine the correct no-selection behavior by
  reading the handler (the click probably should just select the box, not set coords).
  Conservative guard, like the 13966/13326 teardown family — do not restructure the widget.
- **Test:** core GUI-timing bug. Option (1) a `tests/interface/` dogtail test reproducing
  mihle's drag-then-click sequence; option (2) if `_button_release_event` /
  `set_coords` path can be exercised headless with `selection=None`, a unittest in gramps'
  gui test layout asserting no TypeError. Try the headless unit path first (cheaper,
  upstreamable); fall back to interface test.
- **Related:** duplicate 0012659 (2022) — when fixed, both can close. Reference it in the PR.
- **Check upstream isn't ahead:** grep ../gramps selectionwidget.py history for set_coords
  / selection guards since 2024.
