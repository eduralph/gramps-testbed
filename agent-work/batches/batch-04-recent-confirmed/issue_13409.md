## Description
Installing Gramps 5.2.3 AIO on a Windows 11 system logged in as a user with normal privileges gives a UAC request to elevate permissions, as expected.
Install for all users.
<b>After installation is complete, the user is offered to run Gramps immediately.</b>
Unfortunately, this runs as the admin account, so any trees  created are in the APPDATA folder of the admin account, etc.
<b>The next time the user runs Gramps, everything has apparently vanished.</b>

## Steps to Reproduce
described above.

## Additional Information
Either revert to normal user, or else do not offer to run Gramps immediately.

@CameronD Confirming this bug report. I executed the installer in administrator mode on Win10 for a standard user and can reproduce the same problem. A summary of things to keep in mind until this bug is resolved:

When installing Gramps as a standard user and granting admin privileges to the installer:

If installing "for me only" please check installation path and ensure that it is your own %LOCALAPPDATA% and not the admin user's folder
At the end of the installer, uncheck the option to run the application because it will run with the admin user's rights. Instead, complete the install process, and then launch Gramps from Windows to use your own rights.

- **Fix sketch:** in the NSIS installer, drop elevation before the post-install launch (run de-elevated as the invoking user), or remove the run-immediately option when installed elevated for-all-users.
