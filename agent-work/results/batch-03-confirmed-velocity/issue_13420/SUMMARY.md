## What the reporter saw
Person with Birth + Death events (both role Primary) imported via
the Text Import gramplet; the Death event did NOT appear as the
person's death fallback in list views until re-validated with OK in
the editor. snoiraud established on the tracker (note 8) the
reporter's XML was generated by a no-code Android tool with UUID
handles and longer-than-normal change-times; no developer ever
reproduced the symptom on conformant Gramps XML.

## What the test proves
`ImportGramplet/tests/test_xml_death_fallback.py` constructs a
CONFORMANT minimal Gramps XML — events listed before people,
standard Gramps handles (no UUIDs), both events `role="Primary"` —
parses it via the addon's `AtomicGrampsParser`, and asserts:

- `person.get_death_ref()` is not None (the death fallback wires
  up correctly without manual editor re-save)
- `person.get_birth_ref()` is not None (control, same code path)
- The referenced events resolve to Type Death and Type Birth
  respectively

Result on `upstream/maintenance/gramps60`:
```
test_clean_xml_imports_set_death_ref_via_atomic_parser ... OK
Ran 1 test in <1s
OK
```

That is: the addon's atomic XML parser is NOT skipping the
fallback wiring on clean input.

## Why the reporter saw the bug — analysis
The fallback-setting logic lives in gramps **CORE** at
`gramps/plugins/importer/importxml.py:1434-1473` (`start_eventref`),
inherited unchanged by `AtomicGrampsParser` (the addon only
overrides `parse()` for the atomic-DbTxn wrapper). The core parser
spells out its own precondition at line 1451-1452:

> "We count here on events being already parsed prior to parsing
> people or families. This code will fail if this is not true."

`start_eventref` does:

```python
event = self.db.get_event_from_handle(self.eventref.ref)
if not event:
    return       # ← silent skip; death_ref never set
```

If the reporter's XML had any of:
- Events listed AFTER people (violates the precondition)
- UUID handles that didn't match between the events block and the
  eventref `hlink` attributes
- Event-handle collisions or other malformed-input artifacts

…then `event` would be `None`, the early `return` would fire, and
the death_ref would silently stay unset. Re-saving via the editor
then sets it explicitly — exactly the workaround the reporter
described.
