## ===== TRIAGE VERDICT =====
- **Actionable?** yes — easy, current, user-visible. Best "feels responsive" fix in batch.
- **Where:** addons-source `ChatWithTree/`. Branch gramps61.
- **FIRST STEP — repro:** set a dark GTK theme, open Chat With Tree, confirm text is
  low-contrast/unreadable. Current-era (6.0.7) so it WILL reproduce — this is not an
  evaporation-risk item.
- **Root cause (hypothesis — verify):** the addon renders its chat text with hardcoded
  colours (or colours that assume a light background) rather than inheriting the GTK theme,
  so on a dark theme the text is dark-on-dark. Likely in the addon's HTML/CSS rendering
  (if it uses a WebKit/HTML view) or its Gtk text styling.
- **Fix sketch:** make the text styling theme-aware — use the GTK theme's foreground/
  background colours rather than hardcoded ones, OR detect dark mode and switch the palette.
  If it's an embedded HTML view, the fix is CSS (use `@media (prefers-color-scheme: dark)`
  or pull colours from the theme); if Gtk widgets, use the style context's colours. Inspect
  how the addon currently sets colours to pick the minimal correct fix.
- **Test:** hard to unit-test a visual contrast issue. Acceptable to ship without an
  automated test if the fix is pure styling (note that in the PR), OR a light assertion
  that the addon no longer sets a hardcoded foreground colour. Don't over-engineer a test
  for a CSS fix.
- **Check upstream isn't ahead:** grep ChatWithTree history since 2026-03.
