# Issue #13420 — Text Import gramplet: imported Death event not shown as fallback

| field | value |
|---|---|

## Thread — no root cause reached; reporter uses hand-generated XML
Symptom: a person with Birth + Death events (both role Primary) imported via the Text
Import gramplet; the Death event does NOT appear as the death fallback in list views until
re-validated with OK in the editor. snoiraud questions the reporter; established (note 8)
the XML is generated by a no-code Android tool, with UUID handles and longer change-times
than normal Gramps XML. No developer reproduced it with conformant XML.

## ===== TRIAGE VERDICT =====
- **Actionable?** INVESTIGATE — may be a real addon bug OR an artifact of malformed input.
  "Cannot reproduce / invalid input" is a valid terminal outcome (see MANTIS_ACTIONS.md).
- **FIRST STEP — REPRO WITH CLEAN XML (this is the whole decision):** build a CONFORMANT
  minimal Gramps XML — one person, Birth + Death events both role Primary, standard Gramps
  handles (NOT UUIDs) — and import it via the Import Text gramplet on gramps60. Then check
  whether the Death event shows as the death fallback in the People list view WITHOUT
  re-validating.
  - If the death fallback IS missing with clean XML → REAL addon bug (the gramplet skips a
    step the normal import does — likely not triggering the fallback recompute / not
    flagging the event as the death). Proceed to fix.
  - If the death fallback shows correctly with clean XML → NOT our bug; the reporter's
    malformed UUID-handle XML is the cause. Close as cannot-reproduce / invalid input
    (comment ready in MANTIS_ACTIONS.md).
- **Where (if real):** addons-source `ImportGramplet/`. Branch gramps60.
- **Root cause (hypothesis IF real):** the Text Import gramplet adds the event but doesn't
  trigger the recompute that sets the person's cached death-fallback (which a normal import
  or an editor OK does). The "re-validate with OK fixes it" symptom points at a
  post-import recompute the gramplet skips.
- **Fix sketch (only if reproduces clean):** after importing events for a person, ensure
  the death/birth fallback cache is recomputed (call whatever the editor's OK path calls,
  or commit the person so the fallback is recalculated). Determine the exact call by
  comparing the gramplet's import to the normal XML import path.
- **Test:** addon test importing clean minimal XML, asserting the person's death fallback
  resolves to the imported Death event without manual re-validation.
- **Note:** do NOT use the reporter's XML as the test fixture (UUID handles / non-standard).
  Build a clean conformant fixture.
