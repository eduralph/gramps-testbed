## Description
The Family Edit window changes the order of the parent families of the children of the edited family. The order is important, see e.g. "Main parents family" in the wiki: 
https://gramps-project.org/wiki/index.php/Main_parents_family_in_Gramps

## Steps to Reproduce
(Names of people are only suggestions to explain the steps to reproduce.)
- Create and open a new database
- Create a new person "proband"
- Create a new parent family for "proband", only with a new father "F"
- Create another parent family for "proband", only with a new father "M"
- "proband" should now have two parent families. Go to the "Relationships" view and click the "Change order of parents and families" button. Verify that the family in which "F" is father is the first in the "Parent relationships" list and the family in which "M" is mother" is the second.
- In the "Relationships" view, in the section of the parent family with father "F", click the pen/edit button
- In the "Children" embedded list, click the "+" button
- Add a child named "S".
- Click "OK" in the Child Reference Editor without any changes.
- Click "OK" in the Family Edit Window without any further changes.
- In the "Relationships" view, the family with the mother "M" will be listed first and the family with the father "F" and the child/sibling "S" will be listed second. You can also see the changed order by clicking the "Change order of parents and families" button.

## Additional Information
I tried to debug this and was able to trace it back to the transaction before the family edit window closes. The two lists of child refs that are compared ( https://github.com/gramps-project/gramps/blob/03e27e7d511752b9608eefc4267b2c58b770b4a8/gramps/gui/editors/editfamily.py#L1308-L1309 ) don't have the same refs (different instances) even if the refs contain unmodified data.

## Tracker discussion (Mantis notes, scraped)

**Note 1** (aviansid - 2026-04-26 10:42)

I think the diagnosis is correct. The two lists of child refs are compared but Python is using identity comparison. orig_set and new_set contain different instances representing the same children so difference() treats every existing child as both removed and re-added. The fix would be to compare by handle instead. I plan to work on this today.
