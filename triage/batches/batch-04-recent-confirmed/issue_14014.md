## Description
While attempting to verify a backup and restore, the backup process works without errors.  However, while importing the backup file into a new tree the restore process fails with 'string index out of range' error.

Previous attempts have been to:

a) Backup from Gramps-Web and restore to Gramps-Web.
b) Backup from Gramps on Windows and restore to Gramps-Web.
c) Backup from Gramps on Windows and restore to Gramps on Mac.

All attempts result in the same error.

## Steps to Reproduce
Backup from either Gramps-Web or Gramps on Windows and attempt to import to Gramps-Web or Gramps on Mac.

## Additional Information
Also, please note, that running 'Verify the Data...' and 'Check and Repair Database...' execute without errors.

**Note 7** (mattwenger - 2025-10-15 17:53)

OK, I've tracked down the issue:

The offending XML was <daterange start="1911-09-01" stop=""/>. Note the empty 'stop' as indicated by the error trace.

This came about because I had chosen a date type of 'Range', but had only entered the beginning date. I left the ending date blank. I remember doing this, as this was the first time I had used the type 'Range' for a date. I was expecting to come back and enter the ending date once I had tracked down the data.

This was entered into my tree using Gramps Web (not Gramps desktop). However, I often sync between the Gramps Web and Gramps Desktop. The date was associated with a 'Residence' event. Opening up the event using Gramps Web indicated no error. Opening up the event using Gramps Desktop, the date field was clearly in error, shown in red text, the same in the 'Date selection' pane.

To further test this, I changed the type of date (from 'Range' to 'From'), exported again and reimported without errors. I tested by exporting from Gramps Desktop and Gramps Web and both were successful.

Further testing with Gramps Web, I found the following:

I was able to create a new 'Residence' with a 'Range' date, enter in the beginning date only (omitting the ending date) and save it without issues.
When attempting to edit the residence date as a 'Range', I note that I cannot save it without a valid ending date.

Performing the same test with Gramps Desktop shows an obvious error if the ending date is missing and the date reverts to 'Text only' upon creation.

So, it seems that Gramps Web is missing data validation on date type 'Range' when it's initially created. Validation works when editing.

Also, it would be nice if this type of error was detected when running Tools > Utilities > Verify the Data..., especially as there is a checkmark for 'Identify invalid dates'.

Please let me know if I should file further bug reports or feature requests.
