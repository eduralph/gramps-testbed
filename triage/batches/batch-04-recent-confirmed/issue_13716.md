## Description
Custom types were appended in Filter Gramplet's Type, but adding a new type does not update (Signal/Callback problem)

Restarting Gramps does not rebuild the list of Types. But closing the gramplet and re-adding it to the splitbar causes the menu to be updated.

## Steps to Reproduce
start gramps
create a new Tree database and load
In the (empty) Notes category, check the Filter Gramplet menu for the "Type" parameter. 
    Verify that there is no "GEDCOM import" custom type
import a GEDCOM that has import errors (linked below in the Notes. 
   73 problems are reported for John Cardinal's v.1.05 assess.ged test file)
   check the Notes view and verify that there are 40 Note records with a "GEDCOM import" type 
Check the Types menu in the Filter Gramplet
   There is no "GEDCOM import" custom type (at the bottom or in the appropriate alphabetically sort position)

Close gramps and restart.
   There is STILL no "GEDCOM import" custom type (at the bottom or in the appropriate alphabetically sort position)

Close the gramplet and re-add to the Notes sidebar
   The "GEDCOM import" custom type now appears at the bottom of the menu

**Note 3** (prculley - 2025-05-14 21:32)

This is a known issue. Gramps creates the sidebar filter Types selector when the view is first opened. Gramps reads custom types from your database when the db is opened. If you start Gramps in the dashboard, then open the db, then switch to the other view, the types will show up. And for sidebar filters, Gramps never updates them again. In other places where various types are used, the dialogs that are created will show updated types, since their type selector is created anew every time.

I actually developed a fix for a place sidebar filter as part of my https://github.com/gramps-project/gramps/pull/809 for enhanced places. The concept could be generalized to get these updated, but I never created a PR for that.
