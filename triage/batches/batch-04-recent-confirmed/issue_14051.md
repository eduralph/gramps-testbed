**Note 13** (eduralph - 2026-05-23 16:37)

PR opened against addons-source maintenance/gramps61: https://github.com/gramps-project/addons-source/pull/914

Root cause: the pre-pass in write_report() that fills self.report_app_ref is guarded by if self.dubperson: (omit duplicate ancestors). append_event() then reads self.report_app_ref[self.phandle][0] unguarded whenever Index of Dates / Places / Names is on, so with omit-duplicates OFF and an index option ON the report crashes -- KeyError on the current addon (since the partial fix for 12857 / 12859 added an unconditional dict init), AttributeError on the older version cited in this report.

Fix: inside append_event, populate report_app_ref[self.phandle] on existing entry, so the surviving index Ref pins to the FIRST encounter -- matching the [0] semantic the omit-duplicates path emits, so an index entry resolves to the same canonical document position regardless of the omit-duplicates setting. When the omit-duplicates pre-pass DID populate the table, the populate-on-miss branch is skipped and behaviour there is unchanged.

Empirical parity verified on example.gramps (center I00016): 1365 of 1372 common (place, date) index entries have identical Ref tuples between omit-duplicates ON and OFF; the 7 mismatches all have date "0000-00-00", a pre-existing key collision in index_of_places[place][date] where unrelated empty-date events overwrite each other -- independent of this fix.

The secondary symptom on note 12 (blank Index of Places page with the workaround) did NOT reproduce on example.gramps: omit-duplicates ON yields 656 indexed places, OFF (with this fix) yields 658. The fix does not depend on or worsen that symptom; if it persists with real data, it deserves a separate ticket.

Regression test: addons-source DescendantBooks/tests/test_append_event_index_without_omit_duplicates.py covers the crash and the first-encounter parity (the latter case fails on a naive current-state fallback and passes on the populate-on-first revision).
