- **Where does the fix go?** addons-source (in-tree) — `DescendantBooks/DetailedDescendantBookReport.py`. Branch `maintenance/gramps61`.
- **Root cause (HYPOTHESIS — verify by reproducing):** `self.report_app_ref` is read in
  `append_event` (~line 789) but is only *initialized* on certain settings paths. With
  "Omit duplicate ancestors" UNSELECTED and an index option ("Index of dates"/"Index of
  places") enabled, the init path that builds `report_app_ref` is skipped while the read
  path still runs → AttributeError. This is an **incomplete fix for prior bug 0012857**;
  the earlier patch didn't cover the index-enabled settings combination.
- **Does the reporter's workaround match the root cause?** NO. The reporter's "toggle
  Omit-duplicate-ancestors" is a setting that avoids the broken path, not a fix. The real
  fix initializes `report_app_ref` unconditionally (or guards the read with a sensible
  default) so the report runs regardless of the settings combination.
- **Fix sketch (pending repro):** ensure `report_app_ref` exists before any `append_event`
  call — initialize it in `write_report`/`__init__` regardless of the omit-duplicates and
  index settings, OR guard the read. Determine which by tracing where it's currently built
  and why the index-enabled path skips it. Do NOT just guard the AttributeError if the real
  problem is that the reference map is never populated (you'd silence the crash but produce
  a wrong report) — confirm whether the data is genuinely absent or merely uninitialized.
- **Repro on example.gramps?** YES — konwie confirms (note 10). Settings: "Omit duplicate
