## ===== TRIAGE VERDICT =====

- **Actionable?** yes — but this is the batch's CORE-vs-ADDON decision; treat like 13830.
- **Where does the fix go? — RESOLVE BY REPRODUCING FIRST.** The Forms addon is named in
  the report and is what the user drives, BUT the entire traceback is in gramps core
  (`gallerytab.py`, `buttontab.py`) — there is NO Forms-addon frame in the stack. Strong
  prior: **the defect is in gramps core**, and Forms merely triggers it by hosting a
  GalleryTab in a dialog that gets cancelled. If repro confirms the crash is in core
  GalleryTab teardown regardless of Forms specifics, the PR target is **../gramps**, not
  addons-source. If it turns out Forms does something non-standard with the GalleryTab
  lifecycle, it could be the addon. **This split changes the repo — settle it before coding.**
- **Root cause (HYPOTHESIS — verify by reproducing):** teardown ordering (same family as
  13966). On Cancel, the GalleryTab's widgets are torn down and `self.iconlist` is deleted
  or never re-bound, but a `_selection_changed` callback still fires (via `buttontab.py:320`)
  and calls `get_selected()` → `self.iconlist.get_selected_items()` on the now-absent
  attribute. The selection-changed signal handler outlives the widget it reads.
- **Does the reporter's workaround match the root cause?** No workaround given (you just
  avoid opening the gallery). The fix is a guard/disconnect, not user behavior.
- **Fix sketch (pending repro):** two candidate fixes — (a) in `get_selected`, guard
  `if not hasattr(self, 'iconlist') or self.iconlist is None: return None`; or (b) better,
  disconnect the `selection_changed` handler in the tab's teardown so the callback can't
  fire after `iconlist` is gone. Prefer (b) if the lifecycle allows — guarding the symptom
  (a) leaves a dangling handler. Read the GalleryTab/ButtonTab teardown path on gramps61 to
  decide. Note reporter is on 5.2.2; **verify the crash still exists on maintenance/gramps61**
  before doing anything — core display-tab code may have changed.
- **Repro on example.gramps?** yes for the tree; you DO need the Forms addon installed to
  drive the GalleryTab-in-a-form path. example.gramps + Forms addon + steveyoungs' steps.
- **Test location & type:** if core, the test is awkward — it's GUI teardown timing. Options:
  (1) a `tests/interface/test_bug_0013326_gallerytab_cancel.py` dogtail test in the testbed
  (open a form/editor with a gallery, add+select image, cancel, assert no exception); or
  (2) if the core method can be exercised headless with a torn-down `iconlist`, a
  `unittest.TestCase` in `gramps/gui/.../test/`. Lean toward the interface test — this is a
  signal-after-teardown bug that's hard to unit-isolate. Decide after repro.
- **Related / cluster note:** TEARDOWN-ORDERING CLUSTER member (with 13966). If 13966's
